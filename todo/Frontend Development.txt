State Segregation
- Private data:
information specific to an server process, stay on server only.
- Personal data:
user/player related information, stay on server and also sent to client side. individual response
- Play data:
game data that is sharable or used during gameplay among all playes. stay on server and sent to client side.
- Game data:
stared game parameters, sent by client and stored on server side and used during game play.

This separation will make the data flow easier to manage and provide a cleaner structure for complex use cases. We have break these in 4 chunks because 1 big data set reduce the performance and take longer to finish process, instead 4 small dataset works fast. This is all on API side based on front end state management use case need.

During last upgrade we detected an issue with blur UI with fonts.
This was due to Phase rendering process with paint on canvas or WebGL.
The issue was, in small device some layout elements were looking blur that includes
- fonts
- shadows
This happen because Phaser Text is not rendered like normal browser HTML text. Phaser creates an internal canvas for each Text object, uses the Canvas fillText API, turns that into a texture, and then renders or scales that texture. That extra rasterization or scaling step is why Poppins/Outfit can look noticeably softer or blue than the exact same font in Angular HTML.

so, we moved popups, menus, labels, buttons, icons, and normal UI text to custom Angular/HTML and pass to Phaser and adjust location on canvas and thats the correct architectural solution.

Now, UI is sharp and clear, no blur effect.

For more information on this point search google or ask to AI
"angular phase blur issue with ui font and shadow"

Create a clean, 2D flat, minimalist mobile game UI layout for an American Mahjong app named "Mahjfit". 

The visual style must be entirely 2D flat vector art, inspired by contemporary millennial and Gen-Z lifestyle branding with a smooth matte aesthetic. No 3D bevels, no realistic textures, and no complex realistic drop-shadows.

Color Scheme: Use a soft, modern pastel palette. The main background table is a flat, matte sage-green or light sand color. The UI elements and card sections are clean cream white with thin, crisp dark-charcoal outlines.

Interface Layout Architecture (Vertical Smartphone Screen View):
1. Top Section: A clean, flat header containing a simple back arrow, level title in an elegant editorial serif font, and a round, soft-coral colored pause button. 
2. Center Section (Opponent Displays): Three clean, minimalist rows showing the opponent's exposed tile sets. The tiles are flat 2D rectangular cards with simplified, single-color line art vector illustrations for the suits (bambs, dots, cracks).
3. Active Card Section: A clean, collapsible horizontal panel designed as a flat container with rounded corners (border-radius: 16px). It clearly lists winning line combinations using a highly readable sans-serif font, highlighting matching sets in a soft pastel yellow accent fill.
4. Player Rack (Bottom Section): A prominent flat container holding the player's 13-tile hand. Tiles are displayed as simple face-up flat rectangles with thin borders. Clean Arabic numerals and letters are placed crisply in the top-left corners of the tiles for clear legibility.
5. Absolute Bottom Footer: A floating action row containing large, flat, pill-shaped buttons with solid pastel color fills for "MAHJONG!", "PUNG", and "PASS".

The entire screen must feature high contrast, generous whitespace, clean line weights, and perfect 2D vector alignment optimized for a Figma UI kit design.

Given the amount of refinement you've already done and your goal of a polished, enterprise-quality game, I recommend one structural refactor rather than continuing to adjust percentages.

Specifically, I'd replace the current percentage-based layout with a constraint-based layout engine:

Define fixed (or clamped) heights for:
Top exposure
HUD
PASS
Instruction
Bottom exposure
Keep the side exposures tied to the full table height.
Allocate all remaining vertical space to the discard area.
Continue deriving all values from ResponsiveMetrics so the fixed heights still scale proportionally across desktop, tablet, and mobile.

This is the same type of approach used in professional UI layout systems and will make it much easier to achieve—and maintain—the pixel-perfect look you're targeting without every adjustment causing another part of the layout to regress.

Ad Placement and Trigger Actions
1] 
Main Lobby Screen

Ad Format:
Standard Banner Ads
Adaptive Banner Ads

Placement:
Fixed at the top or bottom of the screen.

Trigger:
The banner loads automatically when the app opens and remains visible while the player navigates the lobby.

2] 
Before the Game Starts

Ad Format:
Rewarded Interstitial Ads
Static Interstitial Ads
Video Interstitial Ads

Placement:
Displayed after the player clicks "Find Match" or "Start Game", before the game board loads.

Trigger:
When the player clicks "Start New Game" or "Join Game", a full-screen ad is shown.
The player can close the ad after 5 seconds and continue to the game loading screen.


3] 
During Gameplay

Ad Format:
Small Banner Ads

Placement:
Displayed beside the player's tile rack without affecting gameplay.


4] 
Rewarded Video Ads

Trigger 1 – Low Points
When a player clicks "Play Game" and has fewer than 30 points, a pop-up appears:
"You don't have enough points to start a game. Watch a short video to earn 10 points, or upgrade to Premium for unlimited play."

Trigger 2 – Watch Video
The player clicks "Watch Now".
A rewarded video ad (15–30 seconds) is played.
The video cannot be skipped.

Trigger 3 – Reward
After the video finishes, the player closes the ad.
A confirmation message appears: "+10 Points Added!"
The player's point balance is updated immediately.

5] 
Game Over / Scoreboard Screen
Ad Format:
Interstitial Ads
Rewarded Interstitial Ads

Placement:
Displayed when the player clicks "Next Round" or "Return to Lobby".

Trigger:
After clicking "Next" or "Play Next Game", a full-screen ad is shown.
Once the ad is closed, the player returns to the main menu or the next game.


---
Explanation of Each Advertisement Type

1] 
Transition-Based Ads (Full Screen)
Static Interstitial Ads
- A full-screen image advertisement that covers the entire game screen.
- Usually displayed between game screens or during transitions.

Video Interstitial Ads
- A full-screen video advertisement that plays automatically during transition points.


2] 
Display & Banner Ads

Standard Banner Ads
- A small rectangular advertisement displayed at the top or bottom of the screen.
- It remains visible while the player uses the app.
- The ad refreshes automatically every 30–60 seconds without interrupting gameplay.

Adaptive Banner Ads
- A responsive version of the standard banner.
- It automatically adjusts its size based on the player's screen dimensions for better visibility.


3] 
Reward-Based Ads

Rewarded Video Ads
- A full-screen video advertisement that the player chooses to watch.
- After watching the complete video (15–30 seconds), the player receives an in-game reward, such as bonus points.

Rewarded Interstitial Ads
- A full-screen advertisement shown automatically during game transitions.
- The player does not need to opt in to view the ad.
- If the player watches the advertisement until the end instead of skipping it, they receive an additional in-game reward.
